# PaperLoop 可交互阅读器：技术审阅与实施规划

状态：设计评审稿，尚未实现。本轮只读取项目代码、PDF 对象信息与 SQLite 文档记录；数据库以 `mode=ro` 打开，没有运行模型、重新解析、修改文档或程序。

## 1. Figure 1 为什么点击不了

这不是单纯缺少一个点击按钮，而是程序尚没有“整张图”的可交互对象。

实查 `MonkeyOCR_2025_v1.pdf`（文档 ID `f9091cd15d594b599bcf882010ec1479`）：

- 全文 14 页、148 个块，类型为 title 1、metadata 2、caption 9、heading 18、text 112、margin 1、table 5；**figure 块为 0**。
- 第 1 页 Figure 1 图注块是 `p1-618718e973-3`，归一化边界 `[0.1743, 0.5529, 0.8264, 0.5792]`。可点击的是页高 55.3%–57.9% 的图注文字。
- 图像实际位于页高约 33.7%–54.0%，此处没有文档 block。`src/main.tsx:42` 仅找鼠标松开点所在的 `blocks[].bbox`，找不到就不执行任何操作。
- `PDFPage` 当前没有双击图表、图对象缩略图、独立图窗、滚轮缩放或图内对象命中逻辑。现有加减按钮只缩放整页，范围约 60%–200%。
- 图 1 是位图图表。PDF 第 1 页图区域提取不到轴标签、图例和柱顶数值的原生文字；现有 PDF.js TextLayer 不会让它们自动可划词。`backend/parser.py:195` 只在整页文字极少或强制重识别时 OCR，而首页有标题、作者和摘要，因此图内文字不会被补充识别。
- PDF 对象层出现 6 条高度重叠的 `Im1` 绘制记录（相同 1598×660 源尺寸）。不能把每个 image 记录直接变成一张独立图；必须考虑绘制变换、裁剪、重叠合并，并以渲染页面和图注作校验。

图 1 实际为多模型分组柱状图，不是六张独立子图；还同时出现 CDM、TEDS、1-Edit 与推理速度 Pages/s。读单柱时不能把左侧成绩轴与右侧速度轴混用。

## 2. 应提供的阅读动作

| 动作 | 用户看到的结果 | 不应发生的行为 |
| --- | --- | --- |
| 单击图表主体 | 整图边框、图号与图注、右栏显示当前对象及“解释这张图” | 不立即发模型请求，不跳走阅读位置 |
| 双击图表主体 | 打开独立图表查看器，保留主阅读器的页码、滚动位置和选区 | 不只是把整张 PDF 放大，不重置阅读会话 |
| 图窗滚轮与拖动 | 以鼠标位置为中心缩放；空格拖动/手形工具平移；提供适应窗口、1:1、复位 | 不与划词拖选互相抢事件，不滚动背后的 PDF |
| 原文或图内划词 | 贴近选区显示“解释 / 翻译 / 提问 / 记笔记”浮条；点击后结果进入右栏 | 不靠松手点把跨行选区误认成另一段，不把外部页面选中文字带入 |
| 单击子图或柱子 | 高亮最小可选区域，右栏有带缩略图的选区卡与范围面包屑 | 不把“圈到了像素”宣称为“已准确恢复数据” |
| 单击表格单元格 | 标明表号、行名、列名、原值；可扩为整行、整列 | 不丢失多级表头、合并单元格、空白与勾选含义 |
| 切换对象并追问 | 每个对象的讨论独立保存，可返回旧对象继续 | 不把同一页不同柱子、表格与正文混在一个历史上下文 |

交互优先级：已经形成的文本选区优先；细粒度模式下最小对象优先；其后是整图。鼠标移动超过小阈值视为拖动，不能在结束时再触发单击。文字上双击保留常规选词；图像主体空白或“放大”按钮打开图窗。图窗开启/选中本身不消耗模型额度。

“独立查看器”第一阶段可以是有独立画布和缩放状态的浮层；若产品承诺真正的独立 Windows 窗口，则需在同一阶段增加桌面宿主子窗口。当前 `desktop/Program.cs` 会把本地 `NewWindowRequested` 导航回主窗口，因此不能只用 `window.open()` 就宣称已经支持独立图窗。推荐桌面最终形态为同源子窗口；浏览器版提供对应浮层。两者复用同一个 FigureViewer 组件和对象上下文。

## 3. 现有数据与接口的缺口

| 层 | 当前实现 | 所需增量 |
| --- | --- | --- |
| 页面布局 | 只有页宽、高、正文块 bbox；缺 cropbox、旋转规范、解析版本 | 独立 page_layouts；明确页面坐标、旋转、对象版本 |
| 图表 | 图注被识别为 caption，没有整图对象和图注关系 | figure/table 对象、稳定 ID、图注 ID、边界、来源、置信度、父子关系 |
| 文字 | 前端 PDF.js 临时 TextLayer；后端原始 words 在聚合后丢失 | 原生文字/图区域 OCR 的 token、字符跨度、行、四边形和置信度 |
| 表格 | 后端部分 blocks 有 `cells: string[][]`；前端 Block 类型也未暴露 cells | 单元格 ID、行列、rowSpan/colSpan、表头关联、单元格坐标、原文/修正值 |
| 图中数据 | 无结构化图表模型 | 可选 chart 区域、坐标轴、图例、系列、类别、单位、数值与证据；按阶段提供 |
| 选区 | `selected` block_id 与瞬时 `region: number[]` | 统一 SelectionAnchor；可持久化、可回放、多矩形/多边形 |
| 问答 | `Question` 只有 block_id、selection 字符串、page、box | anchor_id、parent_object_id、对象类型与布局修订、精确证据引用 |
| 历史 | `context_key` 仅 paper/section/selection/page；图像一律 page:N | 图/柱/文字范围/单元格分别隔离；图页作为上级背景，不作为同一会话 |
| 引用与笔记 | 文字引用落在 block；视觉引用只存 visual_page | 图像/单元格引用记录 anchor 和几何；笔记保留原对象版本和缩略图来源 |

目前视觉问答会在 `src/main.tsx:104` 与 `backend/app.py:282` 统一归入 `page:1`。`ask()` 成功后前端会清掉 region；保存的 chat 仅有 `visual_page`，没有 box，因此“再解释一下这里”可能丢失裁图并串入同页其他问题。下一版必须修正后才适合开放单柱连续问答。

## 4. 坐标与对象模型建议

增加独立布局层，不把新图对象混入需要翻译的原 blocks 队列。

```text
PageLayout
  document_fingerprint, page_number, layout_revision
  media_box, crop_box, rotation, width_pt, height_pt
  objects: [FigureObject | TableObject | ChartPart]
  tokens: [TextToken]       # 原生或OCR，按对象惰性加载

ReadingObject
  object_id, parent_id, kind, label, caption_block_ids
  geometry: bbox + optional polygons/quads
  provenance: parser/version/source/confidence
  verification: detected | user_confirmed | human_corrected
  revision, content_hash

SelectionAnchor
  anchor_id, document_fingerprint, page_number, layout_revision
  target_kind, object_id, parent_object_id
  geometry, selected_text, text_span/token_ids
  table_range OR chart_mark_id
  source_snapshot_hash
```

坐标统一保存为“未旋转可见页面、以裁剪区域左上为基准的 PDF point 坐标”，并完整保存映射到 PDF user space 的变换；现有 0–1 bbox 仅作兼容读取。前端通过 PDF.js viewport 变换与 DOM 实际尺寸互转，DPR 只影响画布采样，不能进入持久化坐标。独立图窗额外施加图区域裁剪和平移缩放矩阵。旋转文字用 quads，跨行选词保存多个矩形，不能只留一个大 bbox。

对象 ID 不由屏幕像素/缩放值决定。第一次确认选区后分配稳定 anchor_id；同一图重复进入可恢复历史。任意局部框选要先保存区域对象，再开始讨论，避免每次微小坐标变化创建新会话。旧 block ID 保持不变。

建议新增独立 SQLite 表保存 layouts/anchors/objects，并为新 chat/note 增加可选 anchor 引用。现有 docs JSON 原字段继续读取，不实施整篇批量重写。修订号与 optimistic concurrency 防止旧识别请求覆盖新的人工作业。

## 5. 图对象识别与图内文字

先利用已有本地 PDF 资源构建候选区域：图片绘制边界、图注邻近关系、矢量密集区、裁剪信息。相同源图的重叠绘制先合并/排除裁剪外区域，不能简单 union 全页或把 logo 当正文图。候选边界须可微调与撤销；识别不确定时保留“框选为图”入口。

图内文字的优先级为：可信原生文本 → 局部 OCR → 用户手动划定/输入。局部 OCR 仅处理所选图区域，识别结果回映射到页面坐标，不走现有整页 OCR 替换流程。只根据置信度与重叠规则选择文字层，防止原生文字与 OCR 重复。旋转轴标签需要对应方向的 token quads；看不清时浮条允许选区域解释，不伪造可选词。

划词浮条监听真实 Selection/Range，限制 start/end 都位于当前页面或图窗文字层。保留原始 quote、token span 和几何；不能假设 NFKC、连字符合并后的 block.text 与 DOM 文本有完全相同的字符偏移。选区释放后浮条应保持到用户取消；操作浮条不应让选区先消失。

## 6. 单根柱子：几何选中与语义读数分两层

**几何层**：在图中点选/框选一个可见区域，可包含柱身、标签或子图。右栏准确显示“图 1 的这一区域”，发送局部高分辨率截图，加整图低分辨率背景、图注和相关段落。此时可以解释可见颜色/形状、相对关系；没有证据就不填写精确数值。这一层无需重建完整图表数据，可较早交付。

**语义层**：结构化识别 chart mark 与图例、类别、轴、单位、数值来源，把它们连接成可验证对象。例如 Figure 1 的某一柱需要明确是哪个模型、哪个文档类别、CDM/TEDS/1-Edit 还是 Pages/s、是否有柱顶数字。只有标签与来源明确时，右栏才显示具体数据卡。通过像素估计高度的值要显示“估读”与精度范围；柱顶数字读取与原始数据下载必须标明不同来源。

不能承诺任意论文中一次点击便准确还原所有图表。先支持普通、非堆叠、非断轴、可见柱状图；复杂叠加/对数/误差条/3D 图形降级为几何区域问答。用户修正系列/数值后保存 human_corrected，后续识别不能覆盖。Figure 1 的 0.84 Pages/s 与 84.5 成绩值必须在验收中证明不会串轴或单位。

## 7. 表格选择与第 5 页人工修正保护

当前人工修正表格为 `p5-97695a748e-3`，bbox `[0.176, 0.468, 0.817, 0.716]`，已有 10×9 cells、经核对的原文/译文和 review_note。cells 本身未包含全部多级表头和组别行，也没有单元格几何。

必须把现有 cells、text、translation、review_note 作为受保护基线。新增几何可以绑定既有 cell 值；没有把握的行列映射保留未确认，不重新识别后静默替换内容。Supporting Tasks、Language 的跨列表头，四类数据集分组、空白、✓、`>10`、`M⁶Doc` 均需保真。

单元格点击选中，Shift 选择连续范围；行首/列头可选整行/整列；合并单元格只出现一个交互目标，依真实 rowspan/colspan 运算。右栏始终显示表号、完整列路径、行标签和单位。空白表格单元格只能称“原表留空”，不能由程序解释为不支持或零。译文表格可用真实 HTML table 渲染并与原页单元格同步，不能继续仅用竖线分隔纯文本充当可交互表格。

## 8. 问答接口与历史

推荐新增布局与选区接口，保持原问答接口向后兼容：

- `GET /documents/{id}/pages/{n}/layout`：只读当前布局与修订；无副作用。
- `POST /documents/{id}/layout-jobs`：明确创建/刷新对象识别或局部 OCR 任务；返回可观察 job，不在读取时偷偷重解析。
- `POST /documents/{id}/anchors`：保存已确认图/区域/文字范围，返回稳定 anchor_id。
- `GET /documents/{id}/anchors/{anchor}/image`：按锚点裁图、限定渲染尺寸，使用可复用缓存。
- `POST /documents/{id}/ask` 扩展 `anchor_id` 与目标类型；后端从自身保存的 anchor 取坐标/对象，不信任前端拼接的类别和读数。
- notes/chat/citations 可选保存 `anchor_id`、layout_revision、geometry、quote 与 figure/table标签；旧记录仍可回到旧 block 或页。

图窗与主窗共享 `activeSelection` 及会话服务。跨 Windows 子窗口通过同源 BroadcastChannel 或桌面宿主消息同步，只同步 doc/object/anchor 标识和操作，不搬运凭据。会话 key 由后端生成，例如 `object:<figure_id>`、`region:<anchor_id>`、`table:<table_id>:cell:<cell_id>`；局部与父图历史可显式切换，但不能自动混合。

后续问题持续附带原选区及其父图上下文；首次回答后不清掉 anchor。视觉证据可点击回到精确图窗位置；即使布局有更新，也应使用原修订几何回看，或清楚标记历史位置需重关联。布局任务与既有翻译队列分开，失败/取消不改变论文 completed 状态，不重花已成功段落的翻译请求。

## 9. 建议分期

| 优先级 | 范围 | 交付门槛 |
| --- | --- | --- |
| P0 基础保护 | 基线快照、布局增量层、统一坐标、稳定 anchor、旧数据兼容 | 不改现有译文/笔记/人工修正；坐标变换测试通过 |
| P1 看得清、选得中 | 整图对象、单击选中、双击图窗、缩放平移、图注联动、原生文本划词浮条、图区域持续问答 | Figure 1 能正常选图、放大、返回，追问不串范围 |
| P2 图内阅读 | 局部 OCR 文字层、图内划词、子图/几何局部选区、单元格/行列选择 | 图内轴标签可划选；表格几何映射不覆盖人工内容 |
| P3 语义图表 | 柱子/系列/图例/单位/数值关联、置信度与人工修正 | 支持范围内准确命中；未支持图表清楚降级，不编造数据 |

P1 先解决用户的“点击 Figure 1 没反应”和“看不清”。P2 让图里文字与表格成为可提问的对象。P3 才承诺某根柱子的数值卡。这几阶段可以在同一产品方案中审批，但验收应分别记录，不能拿静态原型当已实现。

## 10. 具体验收

1. **Figure 1 整图**：点击本体任意非文字位置选择完整图；不误选图注，不产生六个重叠 figure。图注与正文中的 Figure 1 引用可定位同一对象。
2. **缩放回位**：25%–800% 图窗缩放（受源图清晰度限制），指针处位置偏移不超过 2 CSS px；拖动、复位、关闭后主阅读器页码、滚动和原选区不变。
3. **坐标**：DPR 1/1.5/2，页面缩放与窗口宽度改变，以及 0/90/180/270° 页面样本中，覆盖框误差目标不超过 2 CSS px；裁图不得偏向邻接文字。
4. **划词**：原文跨行选择、连字/连字符、图中英文标签、旋转轴标签分别测试；OCR 失败时明确退回区域选择；右栏准确展示选择的原词和图号。
5. **历史隔离**：同页两个柱子各问两轮，再问整图与整页；各自只收到对应历史。重开应用后选区、裁图与历史都能还原，不只回到第 1 页。
6. **语义图表**：以 Figure 1 人工标注的图例、至少十根跨不同类别/轴的柱子为样本，要求选中对象身份准确；速度轴 0.84 Pages/s 不与性能 84.5 混淆。不确定值必须拒绝精确填数。
7. **表格**：第 5 页随机十个单元格、两行、两列、Supporting Tasks/Language 合并表头与空白格核验；数据集组别不算数据行。新几何不改变原 10×9 校正 cells。
8. **内容不回退**：操作前后对旧 blocks 的 id/text/translation/cells/review_note、旧 notes/chats 做语义深比较。新增对象、增量会话可以增加记录；旧记录内容与 IDs 必须保持。
9. **取消与失败**：OCR/布局任务超时、关闭图窗、应用重启、模型断网后能恢复/重试，已有译文始终可读；没有自动重新翻译整篇。
10. **性能与无误触**：缓存对象选择应立即显示；首张图窗不先等待模型。一个双击不得触发两个模型问题；文本拖选、图平移、框选三种手势互不抢占。大图按视口与缩放分级渲染，不持续生成超大整页 PNG。

当前受保护内容（blocks、notes、chats 按键排序后的 JSON）只读快照 SHA-256：`3e57d95f90778725c251afaecc834dc261dc9fdf4d621c6fd3f36a60a033798c`。这是本轮检查时的记录，不作为用户继续阅读后仍须固定不变的全局锁。

## 11. 实施边界

本方案不要求现在安装 MonkeyOCR 或更换解析器。先把可交互对象、坐标和历史设计好，再接入任何增强解析器；解析模型无法代替前端交互与数据保护。当前 `worker.py:132` 的整页替换逻辑会删除该页全部旧 blocks，不能用于这次增量布局增强。正式开发前应先确认 P1/P2/P3 产品范围与独立图窗的形态，然后才进入实现。
