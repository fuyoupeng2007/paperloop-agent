# PaperLoop · 桌面论文阅读器

## Windows 安装版

从 [公开下载页](https://github.com/fuyoupeng2007/paperloop-agent/releases/latest) 安装 `PaperLoop-Setup-0.3.0-win-x64.exe` 后，从桌面打开应用，填入自己的 DeepSeek API 密钥并测试保存，即可导入 PDF。安装包包含 Python 后端、OCR 模型、前端与 .NET 桌面运行环境，不需要安装开发工具。完整说明见 [INSTALL.md](INSTALL.md)。

安装版默认数据目录是 `%LOCALAPPDATA%\PaperLoop\data`，仅监听 `127.0.0.1:8766`。密钥使用 Windows DPAPI 加密保存，不会回显给界面。安装版关闭窗口时停止服务，重新打开后可以继续任务；源码开发版仍使用项目 `data/` 与 `8765`，关闭窗口后保持后台运行。

DeepSeek 调用需要网络和个人 API 额度，相关文本或图像会发送给模型服务；应用本机运行不等于模型离线运行。API 模式当前未接独立联网搜索工具。首次连接会做一次简短模型请求，验证成功再保存；未连接时也可以解析和阅读原文。尚未用真实 DeepSeek 密钥完成端到端实测。

## 原有本机开发版怎么用

1. 双击 `Start-PaperLoop-Desktop.cmd`，或 `desktop/dist/PaperLoop.Desktop.exe`。
2. 窗口显示“ChatGPT 已连接”后，拖入英文 PDF。应用自动解析、翻译并保存进度。
3. 左边读原 PDF，右边读中文。单击图或表可选中，双击可单独放大；放大后用滚轮缩放、拖动平移，右侧助手仍可提问。
4. 在原文或中文译文里划选词句，使用浮条解释、翻译、提问、联网查或添加批注。图表、框选区域和不同文字选区的追问分别保存；“论文背景”可联网整理发表情况、作者资料和研究意义。
5. 原 PDF 上方可切换“单页／连续”阅读，左侧目录可以按章节、图和表定位。
6. 双击图表后，切换“柱子”“图中文字”或“单元格”，点选局部后在右侧追问。Shift 点击两个柱子或两个文字框可组成比较／文字范围；表格选格后可选整行、整列，并导出 CSV。识别文字与柱子信息可以人工修正。
7. 在“论文背景”的作者卡里点击“查身份、关系与 GitHub”，或查找相关／后续工作。个人 GitHub、组织主页、项目仓库分别显示，并标记归属已核实／待核实；旧查证点“更新查证”补充。机构旁的按钮可查机构背景。结果保存查询时间、来源和关系依据。
8. 回到书架，打开“跨论文比较”，选择 2–5 篇已解析论文和比较维度。比较单元格可回到原文段落，比较表可继续追问并导出；阅读页“导出”还提供含笔记、图表问答、局部截图和背景来源的阅读报告。
9. 阅读页点“研究任务”，输入目标，或选择“方法与证据”“复现条件”“作者与 GitHub”。模型根据实际结果选择下一步：检索论文、阅读段落、观察图表、联网查证，最后提交带证据的结论。可以查看过程、回到证据位置、暂停／继续／停止，并导出本次研究报告。

划选原 PDF 的词句后点“批注”，可以保留逐行彩色高亮；在译文里划词会关联对应原文段落。双击图表后可批注整图、框选区域、柱子或单元格。批注可选黄、绿、蓝、粉四色，点击原页上的“批注”标记即可修改；右上“批注”面板支持回到位置、编辑、删除。批注独立保存在本机数据中，并进入 HTML/Markdown 阅读报告，不直接写进原 PDF 文件。

图表随缩放和屏幕像素密度重新渲染，不再拉伸固定低分辨率画布；快速缩放会合并渲染并限制内存。原 PDF 内嵌图片本身的像素仍是上限，超过原图分辨率不会恢复缺失细节。

**原有本机开发版可以继续使用现有 ChatGPT/Codex 登录。** 若登录过期，打开“模型连接”里的本机 ChatGPT 选项，在官方浏览器登录页完成后检查连接。此登录不随安装包分发。

程序、PDF 和阅读记录在本机；翻译与图表解释调用 ChatGPT，需要联网，并使用该账号的 Codex 可用额度。它不是完全离线的本地大模型，也不依赖此对话一直打开。连接方式采用[官方 Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)，登录由官方客户端管理，程序不复制账号令牌。

关闭桌面窗口后，已开始的翻译仍在后台继续。再次双击打开即可查看进度。电脑重启后，重新打开应用会继续未完成任务。暂停会等待当前一批结果保存后停止。

## 功能

- PDF 拖入与去重，支持 50 MB / 100 页；本地解析和扫描页 OCR。
- 标题、摘要、正文、图注逐段翻译，中文标题优先显示，保留原文定位。
- 原 PDF 与中文并排，点击段落互相定位；数字和术语异常会标记。
- 图表目录、整图/整表点选、双击放大、滚轮缩放与拖动平移；连续滚动阅读按可见页加载。
- 原文及中文译文划词后直接解释、翻译、提问或记笔记；右侧跟随选区。
- 论文导读、段落 / 页面 / 章节 / 全篇问答，回答附可核对的原文引用。
- 每段直接提问、一键解释与连续追问；按当前范围查看对话，也可切到全部历史。
- 论文背景联网检索：区分上传版本与当前发表状态、作者身份和研究意义，附来源链接与检索时间。刷新失败时保留上次报告。
- 框选图表或公式解释，使用同一个 ChatGPT 连接，无需单独选择“视觉模型”。图、手动框选区域及选中的词句各自保留对话；历史中的图像依据可返回原选区。
- 阅读位置、笔记、术语表和任务恢复；导出 Markdown、双语 HTML，HTML 可打印为 PDF。
- 图内原生文字与本机局部 OCR 字框、彩色柱子候选、可靠表格单元格及完整表头；局部、整行整列、双柱的独立对话和笔记定位。
- 阅读中联网查词、作者身份与有证据的关系、相关工作入口；已有结果在查询失败时保留。
- 2–5 篇论文按九类维度比较，逐格验证引用、回原文和连续追问；比较与阅读报告可独立导出。

作者姓名、参考文献、公式和页边注记等按原文保留；图表原图保存在原 PDF 中，不会直接改写图内文字。复杂表格与公式仍应核对原页。论文内容中的命令只作为文献内容处理。

局部文字使用可点击的 OCR 字框，Shift 可扩选文字范围；它不保证恢复任意位图的逐字符文字层。通用柱状图先给出几何候选，不确定的指标和值保持未确认。当前 MonkeyOCR v1 的图 1 已按原图核对 43 根柱子的图例、类别、指标、单位和标注值；这些标注绑定该 PDF 的文件指纹，不会套到其他论文。图上标注值也不等于获得了原始实验数据。

本篇表 1 的 90 个数据格和 11 个表头使用已核对内容与源文字坐标对齐，保留 Supporting Tasks / Language 合并表头及空值。其他表格只有网格与既有内容能可靠对应时才开放单元格；复杂表格可继续框选。原始段落和译文不会因局部识别被重写。

比较表来自已解析 PDF 的选取证据，程序验证引用为原文子串；“未找到可核对证据”不表示原论文一定没写。模型对证据的解释仍需核对。不同数据集、单位或硬件下的数值不能直接排名。网页版报告可含最多 24 张局部图像，总图像约 20 MB 上限，超出时保留页码与选区定位。

## Agent loop 与桌面应用

桌面应用是你看到的窗口，负责拖文件、看译文和点击按钮。原来的解析、分批翻译与失败重试属于固定工作流程。新增的“研究任务”才是由模型驱动的 Agent Loop：接收目标 → 选择工具 → 获取结果 → 根据证据决定下一步 → 提交结论 → 检查依据与目标是否满足；检查发现缺口时可以继续补查。

每次任务默认最多 8 步，可设 3–16 步，每步包含一次模型决策，并可能再调用图像／搜索或结论复核。另有任务模型请求上限和原有每篇调用上限；达到限制会保留进度。暂停与停止等待当前请求返回，保存工具证据后不再发起下一步；服务重启后任务变为暂停，由用户继续。研究记录独立保存，不覆盖原文、译文、问答或批注。

PDF 引文须匹配本篇原文，网页资料记录来源，图表解释标为模型观察。结论必须引用实际获得的证据，并经过第二次模型复核；这仍不保证模型判断一定正确。检索只覆盖返回的片段，未找到内容不等于原论文没有。当前不执行任意代码、不自动运行仓库，也不自动开展无限多篇研究。

默认 ChatGPT 连接支持这些工具。兼容 Chat Completions 的 API 可使用相同的研究循环；查看图表需配置可处理图片的模型。目前通用 API 连接未接搜索工具，界面会停用联网选项，不会用模型记忆冒充联网查证。尚未使用真实 DeepSeek 密钥验证。

## 数据与其他连接方式

`data/` 保存你的原 PDF、译文、笔记、登录安装位置和桌面缓存。请勿分享此目录；发布压缩包会排除它。当前只供本机单人使用，服务仅监听 `127.0.0.1:8765`，不做云同步。

“模型连接”允许接入兼容 Chat Completions 的 API，DeepSeek 地址与模型预先填好。高级选项可以修改文字/图像模型、服务地址和每篇请求上限；上限用于约束模型请求，不是页数。密钥现使用 Windows DPAPI 加密保存在独立文件，原 SQLite 中的旧密钥读取时会迁移；接口只返回是否已保存，不返回完整密钥。

## 本机交付与开发

源码入口需要 Python 虚拟环境和前端编译产物；若选择 ChatGPT，还需要已登录的 Codex。给其他人使用时应分发安装包，其中包含所需运行环境与 OCR 模型。WebView2 缺失时由安装程序调用微软引导程序联网补装。安装包不携带个人论文、密钥或登录记录；仅复制其中一个 EXE 仍不完整。

构建安装包需 Windows x64、Python 3.14、Node、.NET 10 SDK 与 Inno Setup 7：在虚拟环境中安装 `requirements-build.txt`，执行 `npm.cmd ci` 后运行 `./Build-Installer.ps1`。脚本编译界面、打包后端、发布桌面运行时、收集第三方说明，并输出 `release/PaperLoop-Setup-0.3.0-win-x64.exe` 与 SHA256 校验值。生成目录与个人数据均排除在 Git 外。

浏览器入口仍为 <http://127.0.0.1:8765>。`Start-PaperLoop.cmd` 是备用的浏览器服务启动方式。桌面源码和构建方法见 [desktop/README.md](desktop/README.md)。

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_flow tests.test_worker_regressions tests.test_codex_bridge tests.test_parser_layout tests.test_translation_validation tests.test_ocr tests.test_research_context tests.test_layout_objects tests.test_qa_anchors tests.test_reading_details tests.test_study tests.test_annotations tests.test_agent_loop tests.test_agent_api tests.test_agent_tools -v
npm.cmd run build
npm.cmd run test:study:ui
npm.cmd run test:agent:ui
```

解析器为 pdfplumber + RapidOCR。翻译流程见 `backend/worker.py`，研究循环见 `backend/agent_loop.py`，允许的研究工具见 `backend/agent_tools.py`，官方登录连接见 `backend/codex_bridge.py`。验证记录见 [VALIDATION.md](VALIDATION.md)。

## 文本识别是怎样做的

有文字层的 PDF 直接提取字符与位置，按版式组合标题、段落、表格及阅读顺序；扫描页使用 RapidOCR。ChatGPT 接着翻译提取的段落，也可解释框选的原页图像。当前并未运行 MonkeyOCR。

MonkeyOCR 最新官方实现已提供 Windows CPU 路线，可作为复杂表格/公式页的后续增强。本机接入评估见 [MONKEYOCR.md](MONKEYOCR.md)：需要单独 Python 3.11 环境，最小 S-Parsing 运行模型约 1.58 GB，另需运行库；尚未安装或实测速度。

联网报告使用 ChatGPT 的真实搜索能力，只传论文标题和首页相关文本。它会把作者自述、外部资料和分析推断分开；来源与陈述由模型整理，程序检查链接格式和引用编号，不代替逐条人工核对。预印本、作者录用公告和正式出版分别表述。失败时显示原因，不以离线模型记忆冒充搜索结果。
